## Локальная генерация на ноутбуке: что известно

Пачка из 10 кадров 2026-10-09 (лог —
`tools/generation/logs/batch10-2026-10-09.csv`, вне git; выдержка — в PR #55):

| Этап | Время | Температура до → пик → после |
|---|---|---|
| Загрузка кодировщика (видеокарта) | 12 с | 70 → 70 → 63 °C |
| Промпт (видеокарта) | 3,3 с первый, 0,4 с следующие | не выше 67 °C |
| Кадр 1280×720, 8 шагов (видеокарта) | 56–60 с | 55–66 → **83–86** → 70–75 °C |

- Пачка — 21 минута, около 2 минут на кадр с отдыхом, без пауз и аварийных
  остановок. Запуск: `generate.py --profile laptop --gguf
  unsloth/Z-Image-Turbo-GGUF/z-image-turbo-Q6_K.gguf --limit 10`.
- **Кодировать промпты только на видеокарте** (умолчание). На CPU —
  88–89 °C на каждом промпте даже в 4 потока.
- **Пик кадра 83–86 °C** — в 4–7 градусах от аварийной остановки (90 °C).
  Раньше в логе было 81 °C только потому, что датчик опрашивался раз в 5 секунд.
  Нужно ли снижать — вопрос владельцу в PR #55.
- **Во время пачки ничего тяжёлого не запускать**: сборка и тесты, запущенные
  параллельно, подняли пик кадра до 89,1 °C; при двух работающих агентах защита
  аварийно остановила прогон на 92 °C, когда генератор стоял на паузе.
- Ноутбук должен быть **на зарядке**: на батарее защита отказывает в запуске.
- Закодированные промпты лежат в `tools/generation/cache/embeds/` (вне git);
  в ветках, отведённых до #55, эта папка видна как неотслеживаемая — не
  коммитить.
- Окружение: `tools/generation/.venv` (вне git, PyTorch XPU), модели в кэше
  `~/.cache/huggingface/hub`. При запуске не ставить `HF_HUB_OFFLINE=1`.
- Карты глубины для новых кадров: `cd tools/depth && pnpm install && node
  depth.mjs` (3 с на кадр, пик 72 °C). Без них тест библиотеки красный.

Бесплатная квота Hugging Face (Space `mcp-tools/Z-Image-Turbo` через MCP) —
ноль с 2026-10-08, запрос 2026-10-09 отклонён. На неё не рассчитывать.

## Как продолжить новой сессии

1. Прочитать [AGENTS.md](../AGENTS.md), [vision.md](vision.md),
   [decisions.md](decisions.md) (с D-022), [generation-plan.md](generation-plan.md)
   и этот файл.
2. `git fetch`, посмотреть эпик #42.
3. Порядок: спросить владельца об итогах плейтеста → замена кадров и ответы
   на вопросы из PR → #39, когда будет компьютер.
4. Работать в стиле первого среза: до трёх субагентов параллельно в отдельных
   worktree, каждый открывает PR и не сливает; основная сессия ревьюит и
   сливает после зелёного CI.

## Грабли этой сессии

- **Лимиты.** Субагенты часто обрываются по лимиту API. В задании требовать
  промежуточные WIP-коммиты и проверку, что агент в своём worktree. Возобновлять
  через SendMessage с тем же агентом; если worktree не создался — запускать
  заново.
- **Незавершённая ветка агента** может существовать только локально: отправлять
  её на GitHub до любой перезагрузки.
- **Фоновые процессы на Windows** (vite, MCP-серверы браузера) не умирают сами
  и держат папки worktree. Требовать от агентов останавливать свои серверы;
  застрявшие — находить по командной строке и останавливать, не трогая чужие
  проекты.
- **Удаление worktree**: `git worktree remove` падает на длинных путях
  `node_modules` — помогает `rm -rf` и `git worktree prune`. В
  `.claude/worktrees/` лежит пустая папка `agent-a159aa38dfef8c583` от более
  ранней сессии — можно удалить.
- **Бракованный кадр**: модель иногда выдаёт картинку не по промпту (вместо
  спальни — город). Каждый новый кадр смотреть глазами до коммита; помогает
  короче описать сцену и задать `seed` в `prompts.json`.
- **Параллельные агенты и общие файлы** (`main.ts`, `docs/decisions.md`,
  `ENGINE_VERSION`, снапшоты): заранее раздавать номера решений и версий,
  сообщать агентам о каждом слиянии, общий контракт задавать до запуска.
- **Эпики**: задачи привязывать как подзадачи, список в теле — без чекбоксов.
- **Служебные скрипты** не запускать из папки репозитория: их временные файлы
  попадают в `git add -A`.
- **Перегрев**: три агента со сборками и тестами держат ноутбук около 70 °C
  при ~50 % CPU; генерацию запускать только через `thermal.py` и только когда
  агенты и сборки не работают.
- **Слияние PR** основной сессией может заблокировать защита Claude Code
  («слияние без ревью»): тогда спросить владельца, а не обходить.
- **Общий браузер Playwright MCP** один на всех агентов: параллельные агенты
  уводят друг у друга вкладку. Давать каждому свой headless-браузер.
