# Карты глубины для кадров библиотеки

Скрипт считает карту глубины для каждого кадра библиотеки сна-фильма: по ней
плеер сдвигает слои кадра, и картинка получает объём (D-024). Решение — D-028 в
[docs/decisions.md](../../docs/decisions.md).

| Файл | Что делает |
|---|---|
| `depth.mjs` | Проходит по `apps/web/public/library/library.json`, считает недостающие карты, пишет `depth/<имя кадра>.png` и поле `depth` в манифест |
| `manifest.mjs` | Размер и путь карты; правка манифеста как текста — меняется только строка `depth` |
| `png.mjs` | Запись 8-битного PNG в оттенках серого с текстовыми полями |
| `thermal.mjs` | Защита от перегрева: датчик Windows, пауза до остывания |
| `depth.test.mjs` | Юнит-тесты (без модели и без сети) |

## Модель

[onnx-community/depth-anything-v2-small](https://huggingface.co/onnx-community/depth-anything-v2-small)
— веса [depth-anything/Depth-Anything-V2-Small](https://huggingface.co/depth-anything/Depth-Anything-V2-Small)
в формате ONNX для transformers.js. Лицензия обоих репозиториев — **Apache-2.0**.
Считается локально на процессоре через `@huggingface/transformers`
(onnxruntime-node), полная точность (`fp32`, 99 МБ). Платные API не
используются; сеть нужна один раз — скачать веса.

Id модели и лицензия записаны в каждом PNG текстовыми полями `Model` и
`License` (рядом — `Source`, файл кадра): в манифесте для них поля нет.

## Запуск

```sh
cd tools/depth
pnpm install        # отдельная установка: в сборку проекта и в CI не входит
node depth.mjs      # посчитать карты для кадров, у которых их ещё нет
```

Повторный запуск пропускает кадры, у которых карта уже есть и имеет нужный
размер. Новые кадры в манифесте (#35) досчитываются тем же запуском.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--library <папка>` | `apps/web/public/library` | Корень библиотеки с `library.json` |
| `--only <id>` | — | Только этот кадр; можно повторять |
| `--force` | — | Пересчитать и те карты, что уже есть |
| `--threads <n>` | `2` | Потоки процессора на модель |
| `--rest <сек>` | `15` | Пауза между кадрами |
| `--pause-at <°C>` | `80` | С этой температуры расчёт ждёт |
| `--resume-at <°C>` | `70` | Ждёт, пока не станет холоднее |
| `--no-thermal-guard` | — | Не смотреть на датчик (компьютер без счётчика Windows) |
| `--revision <rev>` | `main` | Ревизия репозитория весов |

Юнит-тесты: `node --test` в этой папке. Тест «у каждого кадра манифеста есть
карта нужного размера» живёт в `apps/web/src/film/library-depth.test.ts` и идёт
в общем `pnpm test` и в CI — ему нужны только файлы репозитория.

## Что получается

- `apps/web/public/library/depth/<имя кадра>.png` — 8 бит, оттенки серого,
  **половина кадра** по каждой стороне (640×360 для 1280×720). **Светлое —
  близко**: модель выдаёт относительную обратную глубину, она растянута на весь
  диапазон 0…255 по каждому кадру отдельно.
- В манифесте у кадра появляется `"depth": "depth/<имя кадра>.png"` сразу после
  `file`. Остальной текст манифеста не меняется.
- У клипов карты нет: движущаяся картинка проигрывается плоско (D-024).

## Перегрев

Расчёт лёгкий (около 3,5 с на кадр на двух потоках), но ноутбук греется быстро,
поэтому:

- кадры считаются строго по одному, на процессоре, по умолчанию на двух
  потоках, с паузой между кадрами и с пониженным приоритетом процесса;
- перед каждым кадром читается датчик `\Thermal Zone Information(*)\Temperature`:
  от 80 °C расчёт ждёт, пока не станет ниже 70 °C; без датчика скрипт не
  запускается (кроме `--no-thermal-guard`);
- не запускать параллельно с генерацией кадров (`tools/generation`), сборкой и
  тестами.

Это облегчённая защита по сравнению с `tools/generation/thermal.py`: нет
аварийной остановки посреди кадра, проверки питания и файла-замка — кадр длится
секунды, а не минуту.
